## 产品原则与依据

旧 [Work OS 设计](chronicle-work-os-product-plan.md) 强调轻量记录、以真实时间为依据、从工作证据产生认识与后续行动，并由用户确认模型建议。这是设计意图，不代表旧文档的所有设想都已实现。

现有 Board/Focus 复用选中的 Task 工作区，Notes 保留列表与当前笔记、支持调整阅读空间，并在切换笔记前保存。这些实际交互提供了可继承的原则：对象与工作上下文连续，日常维护轻量，一份记录可被多处引用，键盘和鼠标表达同一动作。颜色、圆角和间距应服务于这些原则。

项目功能的完整任务是：查看某段时间的投入与成果 → 选出值得关注的方向或里程碑 → 核对工作证据 → 形成下一步 → 执行后留下新的认识。

## 统一后的交互模型

**一个工作区，持续保留当前期间、筛选和选中对象。** 甘特继续承担并行排期和方向关系的主展示；列表提供相同对象集合的另一种阅读方式。两者选择对象的含义一致，右侧使用可持续阅读与操作的检查面板，大屏允许直接切换相邻对象。显式展开详情时沿用同一内容结构和动作，返回恢复原对象、期间、时间轴与滚动位置。

**按工作动作组织内容。** 选中对象后首先回答目标是什么、本期投入多少、最新进展和下一步是什么；相关 Task、Notes 与回顾作为判断依据。高频的更新进展和安排下一步直接可达；对象属性、归档和历史管理收在次级位置。修改排期只处理排期；完成时才呈现完成标准、未完成 Task 与人工确认。编辑的草稿保留、取消、保存和失败语义须统一定义。

**用同一条路径完成判断、执行与沉淀。** 在当前对象下记录下一步，可显式生成或关联已有 Task 草稿，继承主归属并保留来源；继续使用原 Task/Focus 执行。完成与回顾仍是独立事实，完成后可以立即整理回顾，也可以稍后再做。回顾沿用 Note 正文与编辑器，提供清楚的保存、确认和返回入口，用户不必从另一个页面重新寻找确认位置。AI 在更新进展或整理回顾的动作中辅助起草，来源可核对，采用由用户决定。

日常 Task Log 和 Notes 是已有证据。选中对象后可查看本期实际记录与投入来源，再补充用户的判断；不要求把同一过程重新写成里程碑进展。投入展开到同期间的 Task 贡献，必要时继续核对原始时段。回顾列表先帮助找回标题、期间和核心结论，版本与取证作为进一步核对的入口；没有结论时明确缺失，不自动编造经验。

**投入与排期分别表达，范围连续。** 甘特的计划窗口和统计期间可以不同，界面明确区分；下钻时默认继承统计期间，改变范围必须可见。对象的投入与完成情况不能因时间条太短或未排期而消失。进展显示有依据的更新时间，缺少记录只表示信息不足，不推断项目停滞或无价值。

## 产品验收标准

1. 从本周总览选中里程碑、查看 Note、返回总览，期间、筛选、选中对象和时间轴位置保持连续。
2. 甘特与列表中选择同一对象，看到相同的信息结构和动作；大屏连续比较三个里程碑无需重复开关模态窗口。
3. 更新一句进展、调整日期、安排下一步分别有最短且可预测的路径；退出与保存失败不会意外丢失输入。
4. 从人工确认完成到整理、保存和确认回顾，可以顺着清楚的界面提示完成；也能中途离开后恢复。不会自动完成 Task 或改动已记录工时。
5. 同期间中有投入的短条、未排期和窗外目标仍可发现并比较；Task 数量与工时不被包装成成果完成百分比。
6. 用户能从投入找到具体工作、从日常记录找到近期变化、从过去回顾找到已形成的认识；不必重复写过程记录才能让项目页面有内容。

保留当前数据模型、统计口径、版本冲突保护、备份与撤销能力，以及上一轮已修复的国际化和共用控件。实施应围绕上述完整旅程重构，不用继续堆叠独立弹窗或入口来逐个覆盖字段。现有 [工程验收记录](project-workspace-verification.md) 保留为已完成测试的事实，本文件中的产品验收由本轮新增的持续工作区、对象动作、活动证据和回顾旅程测试另行验证。

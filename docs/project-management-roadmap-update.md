# 项目制路线图体验调整

日期：2026-09-12。初轮实现及 131 项相关测试结果保留在下文。随后按用户反馈调整为统一方向泳道，新增验证见下节；历史测试总数不作为新布局重新跑过整套测试的声明。

当前界面随后按信息层级重构：紧凑时间条、按需预览和右侧对象面板，见[概览设计重构](project-overview-design-refinement.md)。以下统一泳道阶段的密度与截图保留为历史记录。

## 后续调整：统一方向泳道

用户进一步要求所有方向展示在同一张图中，方向不再作为横跨整表的 section。当前实现采用一根时间横轴，左侧为方向和摘要，右侧每个方向一条泳道。里程碑时间重叠时自动分轨，不重叠时尽量复用同一轨道。标题宽度也参与避让，实际时间条仍按日期绘制，不延长排期来容纳文本。

- 目标日期按包含当天处理；目标日和另一个里程碑的开始日在同一天时分轨。只有目标日期显示单日菱形；没有结束日期延续至可见窗口右侧。
- 没有日期及视窗外事项置于泳道底部的明确标记区，保留设置日期和定位按钮。日期修改后自动重新布局。
- 方向摘要留在左侧，不切断所有方向共用的网格。保留手工编辑、LLM 草稿、历史、关联 Notes 及方向折叠。方向列和时间表头在图内滚动时固定。
- 横纵轴仍待讨论：目前暂留横向时间轴。理由是里程碑名称、日期、状态与投入适合横排，同时便于按同一日期跨方向比较；用户有触摸板且滚动低频。纵向时间轴对持续浏览时间有优势，但会让每个方向成为窄列，压缩标题和摘要。未加入双布局切换。

验证：重新构建 Web 与服务后，`project-gantt-ui.test.ts` 6 项、`project-area-summary-ui.test.ts` 3 项及既有 `project-ui.test.ts` 5 项，共 14 项通过（15.0 秒）。新增用例检查 WebKit 实际元素位置，验证共用轴、独立方向泳道、重叠分行、非重叠复用、空方向、包含结束日的边界、目标点、持续型和修改日期后刷新持久化；原 Notes 跳转及摘要流程继续通过。


在最新构建的隔离原生客户端中，用 Computer Use 查看了统一泳道、打开方向摘要编辑器、点击重叠里程碑并读到其 2 篇关联 Notes。真实截图：[统一方向泳道](../artifacts/project-swimlane-update/01-unified-gantt.jpg)。示例仍使用独立 `project-manual-ZGKikS`，额外通过 HTTP 添加 2 个明确标记为演示用途的里程碑来呈现并行和轨道复用，没有修改生产库。没有为截图调用 LLM。独立代码审查另修复长方向名称可能溢入时间泳道的问题，最终 14 项复验包含该修复后的构建。图内 sticky 的横纵滚动行为经代码核查，本轮没有调整原生窗口大小单独验证。

## 本轮反馈与产品目标

上一版截图主要展示数据和表单，未能让用户直接看清工作方向、目标时间安排，以及下一步如何投入。主界面需要让人从整体安排进入进展与笔记。

| 用户反馈 | 对应方案 | 使用后应能回答的问题 |
| --- | --- | --- |
| 希望用甘特图看方向与里程碑 | 项目总览默认甘特图，方向分组，里程碑按计划日期排列；保留列表切换、状态和实际投入 | 哪些目标在同时推进，什么时候计划完成？ |
| 每个方向需要手工或 LLM 总结的最新进展与下一步计划 | 方向有独立、可编辑的进展摘要与下一步字段；LLM 先生成草稿，经审阅和显式采用后更新；保留摘要历史和来源 Note | 这个方向现在走到哪里，接下来准备做什么？ |
| 点击方向或里程碑即可看相关 Notes | 点击名称或时间条打开关联笔记面板，方向汇总下属里程碑并去重；继续打开单篇 Note、带标签进入 Notes 或进入目标详情 | 支撑这项工作的记录、成果与感悟在哪里？ |
| 不喜欢 Notes 下拉框，希望 key in 标签 | 同一个输入框输入普通全文文字及 `#方向` / `#里程碑`；候选选择后形成可删除 token；多对象默认 AND | 哪些笔记同时关联我关心的对象，并包含指定内容？ |

## 保留的模型与边界

- 仍然只有 Area → Milestone 两层；Project 是模块名。Task 主归属仍指向里程碑。
- 方向表示长期责任和关注范围，不人为设置总体完成率或结束日期。甘特图时间条属于里程碑，不用建立时间、实际工时推算计划排期。
- 仅有目标日期时显示目标点，仅有开始日期时显示开放结束；无日期时显示待排期。持续型里程碑不会因为经过时间变长而被表示为接近完成。
- 实际投入、Task 完成数、里程碑手动验收仍是各自独立的事实；相关对象引用不重复计时。
- 方向摘要用于呈现当前判断；回顾用于保留阶段性内容与证据，两者继续保留历史。LLM 不自动更新摘要、Task 或里程碑状态。
- Notes 对象标签引用稳定 ID，改名后仍指向原对象。搜索中的 token 只筛选列表，不修改 Note 正文或引用。

## 关键交互

1. 进入项目总览，默认看到按方向分组的甘特图；可切换周/月、移动窗口和回到今天，保留上次选择的甘特图/列表视图。
2. 每个方向行显示最新进展、下一步计划和摘要更新时间。手工编辑后保存；使用 LLM 时先审阅和编辑，再采用为当前摘要。
3. 点击方向名称、里程碑名称或时间条打开笔记面板。方向中的直接引用、下属里程碑引用和现有 Task 派生来源按 Note 去重。
4. 在 Notes 搜索框输入 `#` 后按名称找对象；候选显示对象类型，里程碑显示上级方向。选择后成为 token，可继续输入全文关键词或下一个对象。
5. 多个 token 与全文关键词共同生效，界面明确标注全部匹配（AND）。在服务端 LIMIT 前筛选对象集合，保留既有全文检索排序与归档含义。
6. 中文组合输入期间 Enter 用于确认汉字；普通状态支持上下选候选、Enter 确认、Escape 关闭及空输入 Backspace 删除最后一个 token。无候选时保留输入并解释原因。
7. 页面地址兼容单个 `projectFilter=area:...` / `milestone:...`，重复参数保存多对象，`q` 保存输入内容。跨页面返回及刷新保留筛选；筛选不触发当前 Note 重新激活或覆盖脏稿。

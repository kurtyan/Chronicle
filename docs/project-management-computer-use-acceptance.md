# 项目制桌面 Computer Use 验收

日期：2026-09-12。执行前设计用例，随后仅用 Computer Use 的点击、键盘输入、滚动和屏幕观察完成业务操作。使用当前代码构建的 `Chronicle Project Test.app` 与独立空数据库；测试数据均从客户端创建。命令行仅用于启动、构建、问题诊断和记录，不调用业务 API 代替页面操作。

## 场景与数据

模拟先规划交付，再执行工作、积累笔记、调整归属，最后完成人工回顾的过程。

- 方向：`验收·系统演进`、`验收·职业成长`。
- 阶段里程碑：`验收·交付目标`，目标为交付可验证的改进，标准为完成两项任务并留下证据。
- 持续里程碑：`验收·分析与复盘实践`，目标为持续练习问题分析与复盘。
- Task：`梳理完成标准`、`执行验收并记录边界`。
- Note：`验收·交付与成长记录`，初始正文含 `V1：先定义验收证据，再实施。`。

## 执行记录

12 个场景均已执行并通过，其中 CU-03、CU-08 各发现一个产品问题，修复后在同一隔离库中重新构建并通过客户端复验。上述编号表达用例依赖；暂停持续里程碑等验证在 Task 仍进行中时执行，以核对是否误改下层状态。

### 发现与修复

- **草稿保存不易发现，Mac 提示不符。** 原界面只有 `Ctrl+Enter 保存` 文本，没有保存按钮；Mac 实际通过 `⌘Enter` 提交。已增加“保存任务”按钮及正确的平台提示，按钮和快捷键共用防重复提交逻辑。Computer Use 专项复验：空标题按钮禁用；第三个 Task 从持续里程碑新建，带正文和系统方向额外引用，双击按钮只生成一个 Task 且关系保留；第四个 Task 在标题中连按两次 `⌘Enter` 只生成一个 Task；第五个 Task 在正文中按 `⌘Enter` 成功保存正文。
- **归属调整关闭后缺少可找回的历史入口。** 原预览和应用成功，但关闭后无法从旧里程碑找回原事件。已补齐相关历史展示；更新客户端并重启同一库后，实际从旧里程碑找到 09:44 的原事件，撤销后 Task 归属、系统方向和成长方向投入恢复，原事件标记为已撤销。

CU-12 最初连续执行“勾选、保存”而未观察中间界面，不能据此认定缺少提示。专门重验确认提示在勾选后、保存前已显示，未修改表单，也未增加二次确认。

# 项目工作区：连续工作流程验收

日期：2026-09-13。设计依据：[整体产品复核](project-workspace-product-review.md)。

本次实现围绕“比较投入与成果 → 核对工作证据 → 安排下一步 → 执行 → 回顾沉淀”的完整流程。上一阶段的国际化、搜索选择器、快捷键和大屏布局继续保留。本文记录本次新增行为；上一阶段测试计数不与本次重复累加。

## 实际行为

| 工作动作 | 实现 |
| --- | --- |
| 比较方向与里程碑 | 甘特与“投入与成果”列表共用选中对象和常驻检查面板。可以直接选择下一个对象；面板宽度可调整。列表按本期投入展示里程碑、完成/待回顾状态、进展和下一步，包括短条、未排期和计划窗口外的对象。 |
| 下钻与返回 | 统计期间、筛选、时间轴位置和选中对象随 Task/Notes 跳转保留。展开详情复用相同对象内容；进入的 Task 刷新后仍能恢复。旧 Notes/Task 标签的返回来源继续有效。 |
| 日常维护 | 更新进展在原位置编辑；排期只编辑日期；完成时才显示标准、未完成 Task 和人工确认。关闭保留草稿，明确丢弃才清除。保存失败、版本冲突、保存期间切换对象并继续输入均有恢复行为。 |
| 核对投入 | 本期总投入展开为具体 Task 贡献，可查看原始时段与本期裁切。相关引用不重复计入工时，Notes 不产生工时。 |
| 查看近期证据 | 新只读活动接口按同一期间展示 Task Log、Note 更新或关联时间；区分记录更新与成果完成。分页固定截止时间，切换对象后忽略旧响应，错误仅影响该区域。片段为静态文本与格式，不加载原文媒体或可执行内容。 |
| 安排下一步 | 显式创建 Task 草稿，继承主里程碑、下一步文字和项目来源；也可选择继续已有 Task。仍通过原 Task 工作区保存、执行，不自动创建或启动任务。 |
| 沉淀回顾 | 完成后可整理回顾；Note 页面提供保存、确认版本和返回。确认等待现有 Note 保存完成并包含期间新增文字。回顾列表显示标题、期间、确认结论；原 Note 后续变化不改写已确认内容。 |
| LLM 辅助 | 方向进展草稿继承当前分析期间；重试沿用原草稿范围。回顾的期间可显式调整，日期和分析预算默认折叠；人工回顾为主操作。采用模型结果仍需用户决定。 |

活动查询使用当前 Task 归属与引用，不冒充任意历史时点的归属快照。Note 时间表示更新或关联，不表示成长或成果发生的准确时间；尚无回顾只表示缺少已确认记录。

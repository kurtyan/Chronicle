# Chronicle 项目制实现计划

日期：2026-09-12。状态：甘特图、方向摘要和 Notes 标签输入筛选已纳入当前功能基线并完成相关验证。本轮 44 项服务测试、26 项项目集成/UI 与 61 项既有回归全部通过，共 131 项；加上前轮通过且本轮未重跑的 Rust 7 项，累计 138 项不同自动测试。原生客户端已重新构建，并通过 Computer Use 验证甘特图、点击方向查看笔记、输入对象标签及交集筛选。实际交付和验证边界见 [实现状态](project-management-implementation-status.md)，本轮方案与验收记录见 [项目制路线图体验调整](project-management-roadmap-update.md)，此前逐项客户端操作见 [Computer Use 验收](project-management-computer-use-acceptance.md)。

本计划将方向、里程碑、Task 归属、Note 双向引用、投入统计、复盘与 LLM 串成完整功能。产品背景见 [历史产品讨论稿 v0.3](project-management-product-design.md)。本计划纳入该稿之后关于持续型里程碑、职业成长、沉淀、标签引用及本轮路线图体验的讨论；发生差异时，以本计划与路线图体验调整中的当前基线为准。用户明确要求与具体实现取舍在下文分别表述。

统一术语：方向的英文为 **Area**，里程碑为 **Milestone**。方向相关类型使用 `Area`，数据表使用 `areas`，外键使用 `area_id`（API/TypeScript 字段为 `areaId`），对象引用类型使用 `area`；中文界面仍显示“方向”。Project 仅是管理模块的统称，不是第三种管理对象。

## 1. 实现目标与采用的基线

用户已经明确的需求：

- 两层管理：方向 → 里程碑，Task 关联第二层；不增加第三层 Project。
- 方向可以是技术大方向、负责的系统，也允许职业成长和 KTLO。
- 两层都能分析投入；总体概览以里程碑投入和完成情况为主体。
- 持续的能力建设能够长期跟踪，并记录实际成长。
- 工作需要总结、感悟和可复用沉淀；LLM 帮助分析、总结与形成洞察。
- 方向和里程碑能以标签的方式被 Task、Note 引用，支持双向追踪。
- 以甘特图查看方向及下属里程碑的时间安排，同时保留投入和完成情况。
- 每个方向显示最新进展与下一步计划，可手工总结，也可用 LLM 草稿辅助总结。
- 点击方向或里程碑即可查看相关 Notes；Notes 主界面使用输入标签的方式筛选，不依赖对象下拉框。

当前采用以下实现规则，其中交互细节属于本计划的设计取舍：

| 事项 | 本计划采用的规则 |
| --- | --- |
| Task 正式归属 | 零或一个主里程碑；方向由该里程碑决定。其他方向/里程碑可以作为相关引用，不分配工时 |
| 里程碑归属 | 每个里程碑属于一个方向 |
| Note 引用 | 可直接关联多个方向和里程碑；关联里程碑即可在所属方向中汇总，无须重复添加父级标签 |
| 标签交互 | Task/Note 元数据区提供对象标签选择、显示和跳转；Notes 搜索框输入 `#` 查找方向/里程碑，选择后形成筛选 token，可与全文关键词组合。普通主题标签继续保留，正文对象提及语法仍属后续增强 |
| 甘特图 | 项目总览默认共享时间轴，每个方向一条泳道；里程碑按计划时间排列，真实日期重叠时自动分轨；概览用紧凑时间条，完整信息按需预览或在右侧对象面板阅读，支持周/月刻度、窗口移动和列表切换；日期缺失如实表示，不从创建时间或实际工时推算 |
| 方向摘要 | 独立保存最新进展与下一步、更新时间和来源。手工编辑可直接保存；LLM 生成不改变当前摘要，审阅后显式采用，保留来源 Note 与历史 |
| 点击查看知识 | 方向名称、里程碑名称或时间条打开关联 Notes 面板；方向汇总直接及下属来源，按 Note 去重，再进入单篇笔记或完整详情 |
| 里程碑类型 | 阶段型有可核对的完成条件；持续型长期跟踪，允许阶段回顾，不显示总体完成百分比 |
| 完成机制 | 用户确认里程碑成果；Task 和证据辅助核对，不自动判定完成。不要求提前拆完所有 Task |
| 复盘机制 | 工作状态与复盘状态独立；允许“已完成 · 待复盘”。LLM 草稿不等于已确认复盘 |
| 历史归属 | 更改主归属解释为整体重分类，历史实时统计随之变化；提供影响预览、记录和有条件撤销 |
| 归档与删除 | 方向、里程碑首版只提供归档和恢复，不提供硬删除；归档不删除历史、不级联改变下层状态 |
| AI 操作方式 | 用户按需生成、检查来源、编辑和采纳；不自动调优先级、改归属、完成目标或排期 |

KTLO 的“日常支持”可作为持续型里程碑的创建建议，不在迁移时自动创建方向、里程碑或任务。职业成长使用同一模型，无专属计时规则。

## 3. 数据与服务设计

下列名称为建议实现名，约束和行为优先于最终文件名。

### 3.1 新增与扩展的数据

| 数据 | 核心内容与约束 |
| --- | --- |
| `areas` | 稳定 ID、名称、描述/关注点、当前重点、跟踪状态、归档标记、revision、时间戳；独立的 `latestProgress` / `nextStep`、摘要更新时间/手工或 insight 来源，以及来源 Note ID、Insight ID 和 Note revision |
| `milestones` | 稳定 ID、方向外键 `area_id`、阶段/持续类型、名称、目标、可选完成标准、状态、可选优先级、可空的 `startDate` / `targetDate`、归档标记、revision、时间戳 |
| Task 扩展 | `primaryMilestoneId` 可空；新增关系版本。未传字段的旧请求保持兼容，不能被当作清空归属 |
| Note 扩展 | 新增独立的关系版本；正文仍沿用原 `revision` 和编辑器 |
| `project_references` | 来源为 Task 或 Note，目标为方向或里程碑；记录明确 ID、建立来源和关联角色。对正反向查询建索引并防止重复关联 |
| `project_events` | 记录目标/标准、生命周期、归属及重要进展变更；包含前后值和版本，支持追踪及校验撤销，不把普通改名当作成果 |
| `project_reviews` | 复盘目标、关联 Note、完成复盘/阶段回顾类型、统计期间、草稿/已确认状态、确认时间及关联完成事件（如适用） |
| `project_review_versions` | 确认时保存 Note 的内容版本、目标和归属快照、来源清单、实际取证内容及确定性指标。已确认版本不可被自动重写 |
| `project_insight_drafts` | LLM 草稿、请求范围、证据指纹与不可变取证包、模型及提示版本、来源覆盖情况、生成状态和时间；与临时后台任务记录分开保存 |

具体约束：

1. 对象标签绑定稳定 ID，不以名称或普通 tags 文本作为关系键。改名不失联，同名对象能通过类型和方向区分。
2. 主归属只有一个事实来源：Task 字段；不再在引用表复制一条用于统计的主归属。
3. 引用表的 Task/Note 来源、方向/里程碑目标都使用明确类型约束和存在性检查；可使用分别可空的外键列及“恰好一个来源/目标”的 CHECK，避免仅靠自由字符串关联。
4. Note 的角色属于“这篇 Note 与这个目标”的关系，支持相关资料、成果、复盘、成长等含义。同一 Note 在不同目标可有不同角色；角色与手工/正文提及等建立来源分开。
5. 首版以显式选择标签建立关系。未来加入正文提及时，手工引用与正文引用可并存，删除其中一种来源不能清除另一种。
6. 方向从里程碑推导、Note 从关联 Task 得到的上下文都不自动写成新的直接引用。列表说明来源，合并时按对象 ID 去重。
7. Note 正文和关系分别做版本校验，关联操作不发送过期的整篇正文。创建复盘、采纳草稿等同时涉及两者的操作，应在同一事务中校验相应版本。
8. 原始日志/Note 的删除或修订会影响当前证据，已确认复盘保留当时版本并标注来源变化。不能假装被删除的原始记录仍可打开。
9. 现有 Task Log 没有历史版本，取证时须持久保存实际输入的原始文本/片段及范围、来源版本，而不只保存 ID/hash。确认记录绑定该不可变证据包；界面分别提供“当时证据快照”和仍可用的“当前原文”。可共享同一证据快照，避免每个目标复制一份。
10. “复盘”关联角色只表达 Note 的用途。阶段里程碑的待复盘/已复盘状态由本次完成事件对应的确认记录派生；加减角色标签不能确认、撤销或删除历史复盘。持续型主要显示最近确认回顾日期，无须构造一次完成事件。
11. 计划开始与目标日期可以分别为空；双端均有值时开始不得晚于目标。方向没有虚构的总体结束日期，时间条不表示实际工时或完成百分比。
12. 摘要正文变化才刷新摘要更新时间和手工来源；改名等无关编辑保留原来源。采用 LLM 摘要须校验它属于当前方向且已采纳为 Note，并同时校验方向和来源 Note revision；不修改来源正文或自动确认复盘。
13. Notes 的多个对象 token 按 AND 查询，使用权威反向关系汇总后去重，并在列表和全文候选 LIMIT 前过滤。筛选只读取数据，不建立引用或修改 Note 正文。

确认快照是同一篇 Note 的历史版本，不是要求用户维护另一篇副本。确认后编辑 Note 形成新的内容状态；旧复盘仍指向当时确认的版本，新确认追加版本。

### 3.2 生命周期

- 阶段型：筹备、进行、暂停、完成、取消；完成后可重开。完成时查看目标/标准、现有证据和未完成 Task，由用户确认。
- 持续型：筹备、进行、暂停、结束跟踪；结束跟踪不计作达成一个阶段成果。按需创建多次有日期的回顾。
- 方向：进行、暂停、结束跟踪；没有整体完成百分比。
- 归档是独立可见性状态，不等于完成或删除；保留历史查询和恢复。父级归档或结束时展示活跃下层的影响，不自动关闭它们。
- Task 全部完成、完成数增加或投入达到目标，都不自动完成里程碑。取消 Task 不计作完成；零 Task 不显示 100%。
- 里程碑完成和复盘确认是两次独立行为。重开后再次完成，应能区分本次完成的复盘与上一次的记录。
- 里程碑类型调整需显示已有标准、完成状态和复盘的影响；不能静默把持续事项转换成已经完成的成果。

### 3.3 服务和接口边界

建议新增 `projectService.ts`、`projectReferenceService.ts`、`workStatisticsService.ts`、`projectReviewService.ts`、`reviewEvidenceService.ts`、`projectInsightService.ts`，按业务职责复用现有 DB、Note、LLM 和事件机制。

| 接口组（建议路径） | 能力 |
| --- | --- |
| `/api/areas`、`/api/milestones` | 增改查、搜索/筛选、归档恢复和详情 |
| `/api/areas/:id/summary-from-insight` | 显式采用已采纳方向草稿的核对后文字，检查方向/Note 双 revision，保存来源与摘要历史 |
| `/api/notes` 的 `projectFilters` | JSON 数组承载多个 `area:ID` / `milestone:ID` 条件；在 LIMIT 前按 AND 过滤，并与既有全文/归档查询组合 |
| 现有 Task 创建/更新 | 可选主里程碑；新建可带初始引用，旧调用继续有效 |
| Task 归属 `preview / apply / undo` | 单个或批量重分类、清空归属；返回影响的时间范围和两层投入，带版本/影响令牌 |
| 里程碑方向变更 `preview / apply / undo` | 同样校验版本，记录历史重分类 |
| `/api/project-references` | 显式引用增删、角色编辑、按来源查询及反向查询 |
| `/api/projects/overview`、`/api/projects/statistics` | 一致的时间范围、截至时刻、两层分组、未归属和明细下钻 |
| `/api/project-reviews` | 创建/关联 Note、阶段回顾、确认、历史版本读取 |
| `/api/project-insights` | 创建异步分析、读草稿/来源、取消或重试、采纳到 Note |

分页、归档可见性、稳定排序、空值含义和冲突响应在接口类型中明确。`primaryMilestoneId` 未传表示保持原值，显式 `null` 表示清空；历史影响由服务端计算，不能相信客户端传来的小时数。对既有 Task，首次归属、改归属、清空及批量变更，无论从原更新接口还是专用接口、HTTP 还是 MCP 发起，都进入同一服务校验关系版本和预览令牌，不能通过原 Task 更新路径绕过。没有历史的新 Task 在创建事务内校验目标即可。

HTTP 与 MCP 调用同一服务。MCP 补齐方向/里程碑增改查、Task 归属、引用、统计、复盘和草稿查询/生成能力；不要求 agent 通过读写普通 tags 绕过校验。已有 Task/Note 工具保持参数兼容，追加日志沿用 Task 归属。

变更使用现有事件机制发布对象、关系、统计和复盘失效通知。HTTP 与 MCP 任一路径改名或改归属后，标签、反向列表、搜索和总览保持一致；前端刷新不能覆盖正在编辑的 Note 草稿。

## 4. 投入统计与历史处理

### 4.1 统一统计口径

唯一投入链路为：`work_sessions → Task.primaryMilestoneId → milestone.areaId`。

- 抽出确定性聚合服务，先以现有 Report 行为建立特征用例，再让新总览、详情及 Report 使用同一结果；不并存两套不同的项目工时算法。
- 查询统一使用半开时间范围 `[start, end)` 和固定 `asOf`。工作日边界、时区和周范围沿用现有设置；期间值与累计值分别标注。
- Session 按范围裁切，运行中时段只计至 `min(end, asOf)`；不把日志文字、Focus 计划/编辑跨度或原始会议跨度另加一次。
- AFK/idle 不作为工作投入。会议只统计实际写入的 Session。
- 每个 Task 的时间只归主里程碑。Note 和 Task 的其他引用不参与工时分配，也不改变主归属的任务完成统计。
- 同一统计范围内：全部里程碑投入 + 未归属 = 全部方向投入 + 未归属 = Report 已记录工作投入。这是两个分组的等式，不能将两个分组总数再相加。
- 归档、取消和结束跟踪不会消除历史投入。筛选视图明确局部合计与全局分母，保留其他项/未归属的解释入口。
- 当前 Report 不是通用的重叠区间去重器。本功能不偷偷改写历史计时口径；异常记录在共享统计层识别、解释和另行修正，所有页面使用一致规则。

### 4.2 重分类和撤销

1. 用户选择新主里程碑，服务端以固定 `asOf` 预览源/目标方向和里程碑、涉及 Task、历史时间范围及投入变化。预览和保存放在同一编辑流程，不额外逐项弹出确认框。
2. 保存时重新验证对象版本、Session 结构版本和影响令牌；新增、结束、修订 Session 或变更相关归属时刷新预览。运行中 Session 的自然时间流逝不使令牌失效，提交结果说明预览后新增的已记录时间及当前汇总，避免正在计时的 Task 永远无法保存。
3. 一个事务更新归属并记录前后状态，不改原始日志或 Session；统计和相关缓存失效。
4. 撤销仅在后续没有冲突变更时应用；否则返回当前差异，让用户重新选择，不覆盖新的编辑。
5. 里程碑换方向采用同样规则；已确认复盘继续保留当时归属和统计快照，标明与实时数据可能不同。
6. 业务从某时刻转向另一目标时，提供“在另一里程碑继续”的新 Task 草稿，保留前后链接；不复制旧时段和日志，不在首版引入同一 Task 按日期分账。

Task 硬删除仍按现有语义影响日志和历史投入，应展示受影响的目标和引用。管理页优先提供完成、取消、移出归属和归档；不能把“移出里程碑”实现成删除 Task。

- 完整起止日期显示时间条；仅目标日期显示目标点；仅开始日期显示开放结束；均为空显示“待排期”。持续型不从经过时间推导完成比例。
- 支持周/月刻度、前后窗口、回到今天、方向折叠；窗口外的排期提供定位，不能夹到当前轴边缘冒充窗口内日期。
- 时间条表示计划，投入列表示所选统计期间的真实记录，两种时间各自标明。调整排期不改 Task 状态、里程碑完成状态或既有投入。

- Notes 面板包含显式对象引用和已有 Task 链接派生的上下文，去重并说明来源；派生关系不写成额外标签，不重复计时。

### 5.2 Notes 标签输入筛选

输入 `#` 后按名称找方向或里程碑，候选展示类型及上级方向；选中后成为可删除 token。普通文字继续全文检索，多 token 与文字共同生效，明确显示“全部匹配（AND）”。保留旧单对象链接，也允许 URL 保存多对象和检索文字。

支持上下选择、Enter 确认、Escape 关闭、空输入 Backspace 删除末尾 token；中文组合输入期间不抢占 Enter。无匹配时不自动创建标签或对象。切换筛选、请求失败或旧请求较晚返回，均不能重新激活当前 Note、覆盖脏稿或触发无编辑 PUT。

## 6. 沉淀与 LLM

### 6.1 先完成可独立使用的人工沉淀

- 里程碑中可以选已有 Note 作为成果或复盘，也可以创建并预关联一篇 Note。
- 提供可选复盘结构：结果与完成标准、关键判断/转折、有效做法与失误、感悟、可复用认识及边界。可以删改，不强制填完每一项。
- 持续型里程碑保存多次阶段回顾：过去与现在的变化、案例/个人贡献、尚未验证的认识和下一次验证方向。
- 同一 Note 可以同时作为业务成果和职业成长证据，只有一份正文、一个原始工作投入来源。
- 相关资料不自动成为成果或成长证据；成长证据可以来自其他业务方向，但不把那些工时再次算入职业成长方向。
- 确认复盘时保存内容版本和来源快照。草稿、已确认复盘、当前 Note 编辑状态分别可见。
- 复盘记录本身不凭空生成工时；若用户实际为复盘计时，仍通过普通 Task 的 Session 记录。

### 6.2 首版 AI：有来源的里程碑复盘与方向回顾草稿

流程：选择目标和范围 → 确定性证据包 → 后台生成 → 查看草稿和来源 → 编辑/采纳到 Note → 用户确认复盘。

方向摘要另有独立的使用终点：手工编辑最新进展/下一步并保存，或生成方向草稿 → 核对观察、建议及证据 → 编辑摘要文字 → 点击采用。采用操作先创建或复用草稿的来源 Note，再更新方向摘要；无需强制跨页操作，也不等于确认一次复盘。保留来源 Note、采用时版本、更新时间和摘要前后历史，后续生成不能覆盖当前摘要。过期或部分覆盖的来源需要可见；版本冲突时保留用户文字供重新核对。

证据包由 `reviewEvidenceService` 建立，包含：

- 目标与完成标准、当前状态及时间含义；当前状态不能伪装为所选期间发生的变化。
- 主归属 Task、原始日志、明确关联的成果/复盘 Note；相关引用内容单列其用途，不能当作另一份投入或个人交付。
- 统一统计服务返回的事实指标；模型不负责算工时、占比或完成数量。
- 来源 ID、时间/revision/内容指纹、统计窗口、时区、截至时刻、总量与已覆盖数量。窗口外背景单列。
- 证据缺失、删除、上下文超限或无法完整覆盖时的说明。较早的关键记录不能因“只取最近 10 条”而静默遗漏。
- 实际送入分析的原始内容快照和引用片段；来源清单、指纹及内容一起持久保存，确认复盘绑定同一证据包。

长记录按可追溯来源分块处理，最终结论仍能回到原始记录。已有 AI 摘要可作辅助索引，不能作为全部证据再递归压缩。显式设定输入/输出预算和有界并发，不以“请求成功”证明信息覆盖完整。

草稿采用明确结构：观察及引用、可能解释、反证/证据缺口、需要用户补充的感悟、建议验证。不存在的来源 ID 和结构错误应被校验拦截；数字使用服务端事实字段，不采纳模型自算值。语义性推断保持待验证，不能仅因有引用就标成已证实。

运行规则：

1. 复用现有 LLM 设置、调用日志和后台任务/SSE；复盘有明确可配置预算，不修改原有连接测试的预算规则。
2. 以目标、范围和证据指纹标识请求；相同请求合并运行，较旧结果不能覆盖较新请求。
3. 生成期间来源变更时标为过期快照；用户可核对旧来源或重新生成，不能静默把旧结论标成当前事实。
4. 失败、超时、截断和服务重启只改变运行状态，保留最后成功草稿和确认版本。不能照搬现有 taskContext 失败覆盖缓存的分支。
5. `background_tasks` 只保存临时执行状态；其历史清理不能删除持久草稿、确认复盘及证据版本。
6. 采纳到 Note 走版本检查；再次生成产生新草稿，不覆盖用户已写正文或确认版本，不自动完成里程碑。
7. 日志/笔记内容仅作为分析资料，不能当成系统指令或授权执行修改。模型输出按既有安全渲染路径展示。

无 LLM 时，两层管理、统计、关联、手写沉淀和复盘确认仍完整可用。

### 6.3 后续增强

基础首版完成后，再增强跨里程碑的案例比较、已验证方法复用、相似问题知识找回，以及规划时的完成标准建议。每条洞察保留事实、解释与建议的界限，区分个人贡献和团队结果，不用工时、Task 数或 Note 数生成“能力提高了多少”的分数。

甘特图、方向摘要和 Notes 标签输入筛选已纳入当前范围。自动周期分析、自动排期、依赖驱动排程、多目标工时分摊、总体完成百分比、外部 Vault 同步和新的完整知识库仍不在当前范围。

## 8. 数据迁移、兼容与恢复

1. 开发和测试先使用隔离库；实现迁移前制作可恢复的完整备份，区分 DB 快照和含附件的导出包。
2. 增量建表/补列，旧 Task 的主里程碑默认为空，普通 tags、日志、Note 与 Session 不转换。旧 KTLO 标签不自动成为方向。
3. 迁移可重复执行；关系和对象外键/检查约束验证后提交。旧数据的未归属可查询、批量预览整理；LLM 只能提供候选。
4. 全 SQLite 导出可包含新表，但必须验证导入后 `initDb()`、孤儿清理、全文索引重建不会删除新关系。扩展搜索 kind 的 CHECK 时保留并重建现有三类文档。
5. 如果确认版本存储带附件的 HTML，扩展跨目录导入时的附件 URL 重写列清单；测试正文、复盘版本和附件都可读取。
6. 服务重启、备份恢复和索引重建后，比较对象数量、引用数量、确认版本和确定性统计；不能只验证导入接口返回成功。
7. 明确 schema 版本及兼容边界。不要将旧二进制直接运行于未经验证的新库；回退使用匹配的升级前应用和备份，并说明如何保留升级后新增数据。
8. 方向/里程碑先归档恢复；现有 Task/Note 主动删除需清理对应新引用，并在确认复盘中标注来源不可用，不静默删除全部复盘历史。复盘及证据快照不采用随原 Task/Note 级联删除的外键策略；原文删除后保留来源标识和快照，避免新外键意外阻塞原有删除流程。
9. 本轮补列时，旧里程碑 `startDate` 保持空，旧方向摘要为空且没有虚构更新时间或来源；不根据创建日期、历史工时或已有 AI 文字自动填入计划和摘要。

## 10. 完成定义

用户能够把日常 Task 归入里程碑，用标签从 Task/Note 双向找到方向和里程碑；在甘特图查看目标排期、方向最新进展及下一步，同时比较同口径投入与真实成果；点击目标直接找到关联 Notes，并在 Notes 用输入标签组合筛选；完成或持续推进后留下可找回的复盘和成长记录；按需获得有来源、可修改和显式采用的 LLM 草稿。旧数据、日常执行流程、Note 保存和备份恢复必须经本轮相关验证保持可用，完成与否以实现状态记录为准。

本计划不创建用户的真实方向、里程碑、任务、周计划或自动化。实施阶段和技术细节服务于产品能力，不替用户决定具体工作安排。

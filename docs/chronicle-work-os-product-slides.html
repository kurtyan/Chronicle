Chronicle Work OS

以时间为主线的个人工作操作系统

Chronicle 的核心不只是任务，而是还原真实工作日：时间花到哪里、当前该做什么、工作留下什么知识、如何提升效率。

时间管理Take over、AFK、会议、KTLO、Idle 都进入统一时间线。
任务执行Day Script 牵引注意力，任务和日志承载执行过程。
知识沉淀从日志、会议、任务中提炼 Notes，按 Area 聚合上下文。
LLM 助理识别、转换、计划、总结、建议，而不是替你静默管理。
01 / 08产品重新定义
Design Principles

设计理念：让 Chronicle 贴近真实工作，而不是强迫工作迁就系统

1

时间是真实主线

任务、会议、空闲、打断、恢复都应该落到同一条时间线里，Report 才能解释真实工作日。

2

标签优于固定类型

KTLO、需求、调研、会议、Bug 可以叠加。旧 task type 应弱化，Area + Tags 更符合现实。

3

低摩擦捕获

会议补录、KTLO 快速创建、日志后续提醒，都应该几秒内完成，不进入复杂管理模式。

4

LLM 做转换器

LLM 负责识别标签、提取 follow-up、生成计划、总结知识和效率建议，重要写入由用户确认。

05 / 08信息组织模型
Follow-up Detection

日志里的“稍后跟进”应该变成提醒和醒目标识

Task Log Entry

已经发给 Jack 确认，2 小时后跟进一下。

Chronicle 识别结果

提醒时间：今天 16:30
提醒内容：跟进 Jack 确认结果
来源：当前 task log entry
界面：Today + 原日志醒目标识
实现策略：明确时间表达先用规则识别；模糊表达由 LLM 建议；默认生成 suggestion，用户确认后创建 reminder。
06 / 08Follow-up 识别
LLM Productization

LLM 的五类产品化用法

创建时识别

Quick Capture 自动建议 title、area、tags、是否 KTLO、估时和优先级。

记录时识别

从 log 和会议纪要中发现 follow-up、action item、风险、决策、知识点。

计划时生成

根据 pending tasks、会议、可用时间生成 Day Script 或重排剩余时间。

复盘时总结

按天、周、Area 总结进展，并结合时间数据给效率建议。

查询时召回

从 task、log、meeting、note 中恢复项目上下文，回答必须带来源。

LLM 的定位：识别、转换、总结、建议。关键写操作需要确认，避免把错误自动写进系统。

Roadmap

Roadmap：先补齐真实工作捕获，再形成智能复盘闭环

近期 1-3 周

立刻可落地

1Record Meeting：补录会议，生成 task/log/session，处理 overlap split
2Area + Tags 基础改造，弱化旧 type
3Follow-up Reminder MVP，规则识别 + Today 提醒
4KTLO Quick Capture，LLM 建议标签
5Report 增加 focus / meeting / KTLO / idle 分类
中期 1-3 个月

形成闭环

1Day Script：当前 block、顺延、跳过、重排
2Notes MVP：关联 task/log/area，LLM 生成 note draft
3Area Dashboard：任务、时间、notes、follow-ups 聚合
4Time Analytics v1：计划偏差、切换频率、效率建议
远期 Think Big

Work OS

1Planner / Timeline / Gantt：ETA、deadline、依赖、过载检测
2Work Pattern Intelligence：拖延、估时偏差、高效时间段分析
3Knowledge Graph：Area、Task、Log、Note、Meeting、Reminder 互联
4API / MCP：外部 agent 可控访问 Chronicle
